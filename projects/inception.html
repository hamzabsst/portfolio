PROJECT STUDY / INFRASTRUCTURE

Inception

A WordPress stack built from custom Dockerfiles, with service isolation, persistent data, health checks and file-mounted secrets.

Docker · NGINX · MariaDB

Repository ↗

The problem

Run a persistent WordPress application as separate services, with a clear entrypoint and explicit dependencies.

A design decision

Use the inception bridge network for service discovery. NGINX and WordPress share the application volume; MariaDB has its own data volume. Compose secrets grant password files only to the services that need them.

A debugging edge case

A container being started does not guarantee it is ready. WordPress depends on healthy MariaDB and Redis services; NGINX waits for healthy WordPress. A startup failure can be investigated one dependency at a time.

A possible next iteration

A useful next iteration would add repeatable backup/restore tests and move host-specific volume paths into a deployment configuration.
