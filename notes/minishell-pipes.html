How pipes work in Minishell

Two descriptors connect the output of one process to the input of another.

Start with the pipeline

ls -l | grep ".c" > files.txt

The shell splits this into two commands. The pipe carries the bytes printed by ls to grep. The redirection sends grep’s output into a file.

Connect the processes

In this implementation, the parent creates a pipe when a command has a successor, then forks a child. The child uses dup2 to connect its input and output descriptors. The next child reads from the preceding pipe.

The shell also waits for its children and records the final command’s exit status.

Closing is part of correctness

A pipe reader sees end-of-file only when every write descriptor for that pipe is closed. Keeping an unused write end open can leave the reader waiting. Each process therefore needs a clear list of descriptors it owns and descriptors it should close.

Read the source

parent.c creates and closes pipes; childs.c connects the descriptors. For the underlying behavior, see the Linux pipe manual.
